# Hasamex Research AI

An AI-powered expert-call intelligence application built for the Hasamex AI Engineer technical case study.

The application analyses three expert-call transcripts covering robotic surgery adoption in France, Germany, and the United Kingdom. It converts the calls into evidence-grounded research insights while preserving traceability to the original transcript.

## Features

- Ask questions across all expert-call transcripts
- Answer the supplied interview guide
- Extract exact supporting quotes
- Display source timestamps and expert metadata
- Identify common themes across calls
- Compare market-specific perspectives
- Distinguish genuine disagreements from differences in emphasis
- Browse the original timestamped transcripts
- Light and dark interface modes
- View the RAG architecture directly inside the application

## Markets Covered

## Grounding and Citation Design

A key design goal is preventing the language model from inventing citations.

The LLM generates the analytical synthesis, but the displayed quotes and timestamps are not generated by the LLM.

During parsing, every transcript segment retains structured metadata including:

- Expert
- Role
- Market
- Timestamp
- Speaker
- Exact transcript text
- Source file

The metadata stays attached to each retrieved passage and is rendered directly by the application.

This makes the evidence traceable back to the supplied transcripts.

## Market-Balanced Retrieval

A standard global top-K semantic search can allow one transcript to dominate the retrieved context.

For comparative questions, the application retrieves relevant evidence independently from France, Germany, and the United Kingdom before passing the evidence to the language model.

This improves cross-market coverage while still using semantic retrieval.

## AI Grounding Rules

The generation layer is instructed to:

- use only supplied transcript evidence
- avoid inventing facts, numbers, quotes, experts, or timestamps
- preserve numerical qualifications and scope
- distinguish agreement from differences in emphasis
- avoid manufacturing disagreements
- state when available evidence is insufficient
- avoid treating a forecast for selected centres as a national market forecast

## How to Run Locally

### 1. Clone the repository

```bash
git clone <YOUR_REPOSITORY_URL>
cd hasamex-ai-case-study
```

### 2. Create a virtual environment

```bash
python -m venv venv
```

Windows:

```bash
venv\Scripts\activate
```

macOS/Linux:

```bash
source venv/bin/activate
```

### 3. Install dependencies

```bash
pip install -r requirements.txt
```

### 4. Configure the Groq API key

Create a `.env` file in the project root:

```env
GROQ_API_KEY=your_groq_api_key
```

The `.env` file is excluded from Git through `.gitignore`.

### 5. Run the application

```bash
streamlit run app.py
```

Open the local Streamlit URL shown in the terminal.

## Key Engineering Decisions

### Deterministic evidence metadata

Quotes and timestamps are taken directly from parsed transcript metadata instead of being generated by the LLM.

### Semantic retrieval

SentenceTransformer embeddings allow questions to retrieve conceptually relevant passages rather than relying only on keyword matching.

### FAISS

FAISS provides lightweight local vector similarity search suitable for this small case-study corpus.

### Market balancing

Comparative queries retrieve evidence from each market to reduce single-transcript dominance.

### Cached AI resources

The Streamlit application caches the analysis engine so the embedding model and FAISS index are not rebuilt on every UI interaction.

## Limitations

This demo operates on a very small three-call dataset.

Retrieval quality depends on the semantic similarity between a question and individual transcript segments. For a production system, I would consider question-answer-aware chunking, persistent vector storage, retrieval evaluation, reranking, structured output validation, and automated groundedness testing.

The application should therefore be viewed as a case-study prototype demonstrating the architecture and product workflow rather than a production research platform.
